# CLI structural integration: the Tagma pipeline is now the default

The structural enumeration introduced by issue #40 lived in the library and
the benchmarks; `ev verify` still ran the O(N) cartesian expansion. This
devlog records the integration that makes the structural pipeline the CLI
default, closes issue #42, and unlocks the two CLI tests that were ignored
for speed.

## What changed

`ev verify` now calls `evaluate_structural` instead of `expand_all` +
`evaluate_all`:

- `src/verify/compose.rs` gains `raw_total_combinations`, which computes the
  cartesian product size from the field domains without enumerating the
  space, sharing the overflow and `MAX_COMBINATIONS` guard with `expand_all`.
- `src/verify/evaluate.rs` gains `evaluate_structural`: it returns the raw
  total plus the evaluations of the structurally valid subset, generated by
  `StructuralEnum` and evaluated by the existing `evaluate_all`.
- `ReporterCapable::report` gains a `total` parameter. The reporters derive
  `failed = total - passed`, so the counts stay authoritative even when the
  evaluation list holds only the structurally valid subset. The simulate
  channel keeps `expand_all` and passes `evaluations.len()` as the total, so
  its behavior is unchanged.
- `main.rs` routes `verify` through `evaluate_structural` and passes the
  total to the reporters.

## Measured result

| Metric | Before | After |
|---|---|---|
| `ev verify` CVA6 full (33.5M raw) | 10.4 s | 0.21 s |
| Evaluation rows for CVA6 full | 33,554,432 | 196,608 (valid subset) |
| CLI tests ignored for speed | 2 | 0 |

The counts are unchanged on every committed fixture. For fixtures with only
runtime constraints (sample, tagma decoder) the structural subset is the
full space, so the evaluation lists are identical to the old pipeline.

## Tests

The two ignored CLI tests now run in the default suite and assert the
summary counts from text output (16,384 / 2,560 / 13,824 for the R4 fixture
and 33,554,432 / 196,608 / 33,357,824 for the full fixture). Three lib-level
tests in `tests/structural_enum.rs` pin `evaluate_structural` against
`expand_all` + `evaluate_all`: a runtime-only fixture, a structurally
constrained fixture, and an enable_mask fixture (alu_ext). The enable_mask
differential test compares the distinct passing sets; it also documents
that the mask collapses the funct7=0 combos (rd forced to 0), so the
counted valid total (4,096) exceeds the distinct vector count (3,648).

`evaluate_structural` carries an invariant guard: it returns an error when
the emitted combination count exceeds the raw total, so a misclassified
structural filter or an over-emitting generator fails loudly instead of
silently corrupting the failed = total - passed counts.

## run.sh

The 33M fixture assertion is no longer skipped in CI; `run.sh` now checks
the CVA6 full and R4 counts with `_verify_check`, matching the ibex pattern.
